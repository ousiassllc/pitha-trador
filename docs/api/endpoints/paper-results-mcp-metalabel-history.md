# API 仕様: Paper 実績 MCP の `metalabel_history` 採用診断

`docs/api/endpoints/paper-results-mcp.md` §3.5 `metalabel_history` の分割章（行数上限のため別ファイル）。issue #1045。引数（`from` / `to` / `limit`）・期間・上限・既存フィールド・`data.prediction_counts`・`data.retrain_skips[]` は §3.5 のまま変わらない。ここは `data.models[]` に足したフィールドだけを定める。

### 3.5.1 `models[]` の採用診断

各モデルについて、保存済みの値だけを読んで返す（名前と定義は Calibration API `GET /api/v1/calibration` の `meta_model` に揃える。記録の無い値は `null` で、0 でも今の `DefaultAcceptanceConfig` の値でも補わない）。実装は `internal/service/paperresultsmcp/query/adoptionview`。

- 実績: `oos_takes`（OOS で較正後に take とした件数）・`oos_days`（OOS が属する JST の取引日数）・`oos_ev_ci` / `oos_auc_ci`（`{low, high}`。定義できない CI は `null`）・`take_rate`（`oos_takes / oos_samples`。どちらかが `null`、または `oos_samples=0` なら `null`）。`prediction_counts.take` / `skip`（`metalabel_predictions` ＝ライブ予測の件数）と `oos_takes`（OOS で較正後に take とした件数）は**別の数**で、突き合わせない。
- `adoption_recorded_status`: `recorded`（`adoption_json` に採用基準がある。Calibration API が `criteria` を出す条件と同じ `min_oos_samples > 0`）/ `not_recorded`（#780 以前の行など。`oos_takes` / `oos_days` の既定 0 は実績ではない）/ `unreadable`（`adoption_json` を読めない）。`recorded` 以外では `oos_takes` / `oos_days` は `null`（0 にしない）で、`criteria` / `comparison` / `gate` も `null`。
- `criteria`: `min_oos_samples` / `min_takes` / `min_oos_days` / `min_ev_lower_bps` / `min_auc_lower` / `alpha` / `resamples`。**そのモデルを判定したときの値**（`seed` は返さない）。
- `numeric_checks`: 次の 5 つを `internal/service/metalabel/training/acceptance.go` の `Judge` と同じ順・同じ不等号で。各 `{actual, required, met}`。`oos_samples`（`oos_samples >= min_oos_samples`）/ `oos_days`（`oos_days >= min_oos_days`）/ `oos_takes`（`oos_takes >= min_takes`）/ `oos_ev_ci_low`（`oos_ev_ci.low > min_ev_lower_bps`。等しければ `met=false`）/ `oos_auc_ci_low`（`oos_auc_ci.low > min_auc_lower`。同）。`met` は `true` / `false` / `null`: `criteria` が未記録、`actual` が未記録（`oos_takes` / `oos_days` は `recorded` 以外、CI は `null`）のとき `null`（判定不明。`false` や 0 にしない）。`actual` は保存された値そのもの（本当に 0 で記録された `oos_takes` は `actual=0`・`met=false`）。`oos_samples` と CI は `adoption_json` と別の列なので、`criteria` が無くても `actual` は値を持つ。
- `first_unmet`: `numeric_checks` を上の順に見て最初に `met=false` になった項目名（`oos_samples` / `oos_days` / `oos_takes` / `oos_ev_ci_low` / `oos_auc_ci_low`）。なければ `null`。`numeric_complete` は 5 つすべての `met` が `true` / `false`（`null` が無い）のとき `true`。**`numeric_complete=false` のときの `first_unmet` は「判明している中で最初」で、実際の最初とは限らない**（`null` の項目の前に未達があったかもしれない）。**`first_unmet` は数値基準だけから決め、`reject_reason` と一致させない**: `reject_reason` は cutoffGate（`llm_model_changed` など）が数値基準の理由を上書きしたり、現行モデルとの比較（`candidate_not_better_than_active` / `active_model_not_comparable`）、変更頻度制限（`model_swap_rate_limited` / `policy_change_freeze`）が決めたりする（`adopt.go`）。数値基準を全部満たす行は `first_unmet=null` のまま `reject_reason` は元のまま返る。cutoffGate に上書きされていない数値基準の理由（`oos_samples_below_minimum` / `oos_days_below_minimum` / `oos_takes_below_minimum` / `oos_ev_ci_not_positive` / `oos_auc_ci_not_above_minimum`）の行では、対応する項目が `first_unmet` になる。`reject_reason` は従来どおりそのまま返す。
- `comparison`: `active_version` / `comparable` / `paired_samples` / `candidate_bps` / `active_bps` / `diff_bps` / `diff_ci` / `active_ev_ci`（CI は `{low, high}`、未定義は `null`）。自由文の `note` は返さない。`comparison_status`: `recorded`（保存されている）/ `not_performed`（採用記録はあるが比較が無い: 採用基準・cutoff を通らず比較まで進まなかった、または現行モデルが無かった。`comparison` は `null`）/ `not_recorded`（採用記録が `not_recorded` / `unreadable`）。
- `gate`: `reason`（固定コード `model_swap_rate_limited` / `policy_change_freeze`。未知の保存値は `other`）と `until`（UTC RFC3339）。自由文の `detail` は返さない。変更頻度制限に当たっていなければ `null`。
- `forward`: `evaluated_at` / `from` / `samples` / `takes` / `days` / `ev_bps` / `ev_ci` / `degraded`（`forward_json` のとおり。時刻は UTC RFC3339）。`forward_status`: `evaluated`（`evaluated_at` がある）/ `not_evaluated`（採用記録があるのに `forward_json` が空。却下モデル・採用直後）/ `not_recorded`（`forward_json` を読めない、または採用記録の無い行で空）。`forward` は `evaluated` 以外では `null`。

返さない: 自由文（`comparison.note`・`gate.detail`）、`params_json`、`feature_names_json`、`oos_calibration_json`、`features_json`、`adoption_json` / `forward_json` の生の文字列、`criteria` のブートストラップ乱数の種（`seed`）。読み取り専用（`mode=ro`）。
