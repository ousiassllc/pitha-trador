# メタ × 品質足切り 2x2 比較（オフライン CLI `cmd/metaablation`、issue #1046）

「メタモデルは価値を足しているか」「entry_quality の足切りは価値を足しているか」を、**同じ期間・同じ入力・同じコスト・同じ資金とリスクの制約**で、**一つの軸だけを変えて**比べる研究用ツール。採用されなかった（却下された）モデルも、保存済みのパラメータのまま再採点する。

**範囲の明記**: これは仕様と検証の道具であり、Paper/Live の設定変更・発注・モデルの active 昇格・DB の写しの取得の許可ではない。利益を保証しない。再学習・再較正はしない。新しい LLM 推論は呼ばない（保存済みの Jev 判断を再利用する）。取引所・証券口座・本番 API には接続しない。

## 現状（重要）

- **DB の写しの取得は別途の承認が要る。今回はまだ取得していない。** 実装とテストは合成データ（テスト内で作る一時 SQLite）だけで行った。実データでの実行は、承認と写しの用意の後。
- **比較用の最小日数・最小件数・意味のある差 δ・検出力は未設定**で、提案は [metaablation-thresholds.md](metaablation-thresholds.md)（実装者の提案。あいりの統計・投資面の確認待ち）。確定するまで**すべての判定は `優劣未確定`**。採用基準（370 take・約 11 bps・`MinOOSDays`）は流用しない。
- 将来、重い比較の実行権限や入力 manifest を MCP で扱えるようにする余地として、manifest は機械可読な 1 つのファイルにしてある。**MCP ツール化は B 完了後の提案に留め、今回は作らず、Issue も自動起票しない。**
- Issue #1010（複数 AI × プロンプトの shadow）は別目的で、基盤・実装は共有しない。

## 手順

`init`（評価の前に、対象モデルと事前登録値を固定する）→ `run`（固定した manifest を実行する）の 2 段。

```sh
# 1. 事前登録。評価窓のデータを読む前に、最新の却下モデル 1 件と全ての規則値を manifest に固定する。
go run ./cmd/metaablation init \
  -db /path/to/COPY.db \
  -asof 2026-11-09T00:00:00+09:00 -from 2026-10-26 -to 2026-11-09 \
  -out /var/tmp/ablation

# 2. 実行。固定した manifest をそのまま実行する。
go run ./cmd/metaablation run \
  -db /path/to/COPY.db \
  -manifest /var/tmp/ablation/metaablation-run1.prereg.manifest.json \
  -out /var/tmp/ablation/out1
```

- `-db` は**写し**。`sqlitedb.OpenReadOnly`（SQLite `mode=ro`、マイグレーションなし、書き込みは失敗する）だけで開く。書き込み可能で開く経路も、`metalabel_models` の `status` を変える経路も無い（テストで固定）。`init` が写しの SHA-256 を manifest に記録し、`run` は実行の前と後で一致を確かめ、違えば失敗する。
- `-out` は DB の写しの**ディレクトリの外**。DB ファイル自身、またはそのディレクトリ以下は拒否する。出力は JSON・Markdown・manifest の 3 ファイルで、既存のファイルは上書きしない。
- `-from`（含む）〜`-to`（含まない）が評価窓、`-asof` が写しの時点（`-to` は `-asof` 以前）。日付だけの指定は JST の 0 時。
- `-seed`（既定 1046）は manifest に残る。**同じ manifest・同じ写し・同じ seed なら出力は完全に同じバイト列**になる（テストで固定）。
- 対象モデルは `init` の時点の**最新の却下モデル 1 件**。manifest にバージョンとパラメータの SHA-256 を固定し、`run` は**そのバージョン**を読む（その後に別のモデルが保存されても拾わない。保存済みの `params_json` の SHA-256 が違えば実行しない）。`params_json` を読めないときは、両層とも「実行不可」とその理由を出す（本体は出さない）。
- コホート・Jev の版（#881・#939）はモデルの `adoption_json` の `trained_cohort` から固定する。記録が無いモデルは `-cohort` の明示が要り、記録と食い違う指定は拒否する。コホートの確認は外せない。**制約**: コホートは質問の版（`question_version`）だけで決まる。評価行の Jev の `model_id` が学習時と違っても、その行は除外しない（独立性の規則は変えない）。Jev のモデルが途中で変わった期間の結果は、その点を含めて読む。
- 事前登録値（既定は同梱の `config/strategy.yaml`・`config/risk.yaml` の Paper とバリア・コストの既定）は `init` のフラグで変えられる（`-min-ev-bps`、`-initial-capital`、`-max-spread-bps`、`-min-turnover-5m-jpy`、`-min-continuation`、`-max-toxic-flow`、`-max-liquidity-stressed`）。変えた値は manifest に記録され、固定される。`entry_quality = good`（Q on）は固定で、フラグは無い。旧 confidence しきい値はどのセルでも使わない。
- 最小日数・最小件数・δ・検出力（`-min-days`、`-min-count`、`-delta-label-bps`、`-delta-replay-daily-return`、`-power`）は、**フラグで与えた場合だけ** manifest に載る。与えなければ未設定のまま。
- **値を変えるのは新しい実行**（実行回数 +1、先の実行は理由つきで列挙して残す）。次の 2 通りがある。
  - `init` をもう一度実行する（規則値・窓・`-min-ev-bps` などを変える場合）: 同じ DB の写し・同じ対象モデルの事前登録が `-out` に既にあるとき、`-supersedes <前の prereg manifest>` と `-new-run-reason "<理由>"` の**両方が必須**で、無ければ拒否する（実行回数 1 から作り直して値を変える抜け道は無い）。前の manifest は変更しない。連鎖の最新でない実行を `-supersedes` に指定することも拒否する。別の写し・別のモデルの manifest は `-supersedes` にできない。
  - `run` に `-new-run-reason "<理由>"` と閾値のフラグを付ける（最小日数などの閾値だけ）: 前の manifest から新しい manifest を作って固定し、`<out>/metaablation-runN.prereg.manifest.json` に書いてから評価する。`-new-run-reason` なしで値を変える指定は拒否する。
  - 同じ manifest をそのまま再実行しても実行回数は増えない（出力が同じバイト列になることを前提にしているため）。実行回数と全比較数は結果に載る（探索を足して比較数が事前登録を超えると、判定はすべて `優劣未確定` に下がる）。
- **窓と embargo の検査**: `-from` はモデルの元 OOS の終端以降でなければならない（`init` がモデル自身の窓のラベルを評価データとして読まないため）。`-embargo` は再学習の既定（30 分）以上（短くすると独立の境界が緩むため、下回る指定は拒否する）。
- **WAL**: manifest の写しの SHA-256 は本体のファイルだけを覆う。`<db>-wal` が空でない写し（チェックポイント前）は `init`・`run` とも拒否する（`PRAGMA wal_checkpoint(TRUNCATE)` 済みの写しを使う）。`mode=ro` で開くと、DB のディレクトリに空の `-wal` / `-shm` ができることがある（内容は無く、ハッシュ対象外。DB 本体は変わらない）。
- **出力先の検査**: シンボリックリンクを解決してから比較する（DB のディレクトリへのリンクも拒否する）。出力 3 ファイルのどれかが既にあれば、1 つも書かない。
- **コードの版**: ビルドの VCS スタンプ、無ければ `git rev-parse HEAD`（best effort。未コミットの変更があれば `-dirty`）、それも無ければ `devel` を manifest に記録する。`run` のコードの版が manifest と違えば、結果に注意書きを出す（同じコードで再現できるとは限らない）。
- **終了コード**: 0 成功（`-h` を含む）／1 失敗（I/O・エンジン）／2 使い方の誤り／3 拒否（manifest が変更されている・凍結されていない、別の写し・別のモデル、WAL 未反映の写し、出力先が写しの中、新しい実行なしの値の変更）／4 実行できた層が無い（理由は結果にある）。

**母集団は 3 段あり、混ぜない。** 一つの表・一つの数字に混ぜた数字は無い。

| | (i) 元のモデル評価（参考） | (ii) 表 1: ラベル層 | (iii) 表 2: 再生層 |
|---|---|---|---|
| 母集団 | 元 OOS の行をガード・適格条件・Risk なしで再採点（参考） | 独立な行のうち適格条件を通った候補（共通）。Risk・資金なし | (ii) のうち、そのセルの Q・M と Risk・資金を通って**実際にエントリー**されたもの |
| 損益 | ラベル基準の `net_return_bps` | 同左 | 再生した約定・出口の円・資金比 |

- **ラベルは proxy**: `net_return_bps` はトリプルバリア（TP/SL 30 bps・10 分・コスト込み。issue #774）の代理で、再生層の約定・出口の損益とは別物。
- **4 セル**: (M off, Q off)・(M off, Q on)・(M on, Q off)・(M on, Q on)。M off は「適格候補に meta フィルタを適用しない」ことで、無条件発注ではない（Risk・資金・出口は効く）。Q on = `entry_quality >= good`、Q off = `entry_quality` の足切りだけを外す（他のガードは当てる）。VWAP 逆張りの候補は Q の対象外なので、別掲して Q の差に含めない。
- **主比較は一つの軸だけが違う 4 組**（Q off→on を M off・M on で、M off→on を Q off・Q on で）。**対角（両方が変わる 2 組）と交互作用は参考**で、判定を付けない。
- **段階ごとの件数**は実際の適用順（適格条件 → Q → continuation → toxic_flow → liquidity_stressed → M → Risk → 約定）で、最初に落ちた段で数える。Q off のセルは Q で落ちていた行が後ろの段に進むので、段の内訳が Q on と変わる。保存特徴・判断と固定ルールで再評価し（保存された先頭の `reject_reason` だけでは復元しない）、復元不能な行は `unknown` として 4 セルから共通に除外して件数と理由を出す。
- **「1 take あたり」と「1 適格候補あたり（skip は 0）」は別の列**。分母がセルごとに違うため。
- **独立評価の定義**: そのモデルの train・calibration・元 OOS の各終端、およびそれらの行のラベル期間（`LabelEnd`）と embargo より**後**の、未来の時系列だけ。`train_start` より前、窓どうしの間、窓の外というだけの行、`llm_cutoff` の前後だけで決めた行は独立に入らない。元 OOS の再採点は「参考」で、独立と書かず、優劣・採用の根拠にしない。embargo はモデル行に保存されていないので、再学習の既定（30 分）を使い manifest に記録する（長いほうが安全側）。
- **ラベル層（表 1）**は判断 ID で対にした差（To − From、skip は 0）を、取引日をまとめて再抽出するブートストラップで評価する。**再生層（表 2）**は経路依存（Risk・同時保有・資金）なので判断 ID の差では評価せず、**全セル同一の初期資金から時系列に連続して再生**した日次損益（円・資金比）の日次差を、日を単位に再抽出して評価する。資金・連敗を日ごとに初期化しない（エンジンが実際に行う日次リセットだけ）。最大 DD は日次資産曲線上の記述で、差の区間は参考。
- **市場データ（`market_snapshots`）が欠けた日**は、再生層だけ「実行不可」とし、期間と理由を一覧で出す。欠けた日をまたぐと状態を引き継げないので、全セル共通の区間に分けて区間別に示し、区間どうしを一つの資産曲線に結合しない。**ラベル層は同じ期間でも実行する**（足が無い判断は `unknown`）。
- **`優劣未確定` の意味**: 区間が 0 を含む、日数・件数が事前登録の最小に届かない、観測した分散で検出できる最小の差が δ より大きい、または事前登録値（最小日数・最小件数・δ・検出力）のどれかが未設定、のいずれか。「差がない」という意味ではない。点推定だけで優劣は書かない。判定は `優位確認` / `劣位確認` / `優劣未確定` の 3 つ。
- **多重比較**: 主要指標（ラベル層の 1 適格候補あたり net bps、再生層の日次リターン）・評価層・比較ファミリ（各層の主比較 4 組）・全比較数（既定 8）・補正（Bonferroni）を manifest に事前登録し、実際の全比較数と補正後の水準を結果に併記する。検出できる最小の差は、観測した日次差の分散と事前登録の検出力から出す（観測した差の事後検出力は出さない）。

## 出力に含まれないもの

JSON・Markdown・manifest は件数・bps・円の集計と manifest だけで、秘密、板や時価の生値、`state_json` / `response_json` / `params_json` の中身は含まない（出力時に検査し、含まれていれば書かない）。manifest にはモデルのパラメータの SHA-256 だけを残す。

## 実装の構成

- `cmd/metaablation`: フラグ処理（`init` / `run`）。
- `internal/service/metaablation/runner`: `Init`・`Run`・出力先の検査・再生層の設定（Paper の既定 + 事前登録値）・再生結果の report への写像。
- `internal/service/metaablation/loader`: 読み取り専用の DB アクセス（却下モデル、判断・ラベル・市場データ、特徴量の復元）。学習・較正の関数はこのパッケージグラフから到達できない（テストで固定）。
- ライブラリ: `manifest`・`independence`・`eligibility`・`labellayer`・`replaylayer`・`stats`・`report`（同ディレクトリ配下）。
