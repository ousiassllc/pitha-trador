# kabuステーションAPI エラー対応（状態確認）

`docs/architecture/kabu-status-mcp.md` が参照する公式表の写しと、状態確認ツールが使う分類。一次情報は次のとおり。

- エラーコード: <https://kabucom.github.io/kabusapi/ptal/error.html>
- 初期設定: <https://kabucom.github.io/kabusapi/ptal/howto.html>

表の文言は 2026-10-03 時点の公式表に合わせている。公式が空欄のセルは空欄のまま。説明文の「kabuSステーション」など公式側の表記もそのまま残す。

状態確認が呼んでよい HTTP は `POST /token` だけである。発注エラー（公式表の「3.発注エラー」。注文 API の `Result`）は写さない。あのコードは発注・訂正・取消の結果であり、この MCP はそれらの API を呼ばない。

接続拒否は公式のコード表には無い。待受が無いときの TCP の結果として `kabu-status-mcp.md` の `not_listening` で扱う。

## 1. HTTP ステータスコード

公式「1. HTTPステータスコード」。

| コード | 定義 | 内容 |
| --- | --- | --- |
| 200 | OK | API呼出し成功 |
| 400 | Bad Request | パラメータ不正 |
| 401 | Unauthorized | 認証エラー（トークン不正など） |
| 403 | Forbidden | アクセス権不正（APIキー不正、口座未開設、アクセス権不足URL呼出しなど） |
| 404 | Not Found | URL不正 |
| 429 | Too Many Requests | スロットリング制限エラー |
| 500 | Internal Server Error | サーバ内部エラー |
| 503 | Service Unavailable | サービス制御（停止中） |

`POST /token` のログイン・パスワード失敗は HTTP 401 で、本文に下表の `Code` が入る。ツールは `http_status` と `code` の両方を返す。分類は `Code` を優先する。HTTP 200 でも `ResultCode` が 0 でなければ失敗であり、その数値を `code` にする。

## 3. 状態確認が使う分類

`kabu_station_status` の `issue` へ落とすとき、公式の意味は変えない。

| 観測 | 公式のエラーメッセージ | 公式の説明 | `issue` |
|------|------------------------|------------|---------|
| TCP の接続拒否 | （コード表の外。待受なし） | | `not_listening` |
| `4001007` | ログイン認証エラー | kabuステーションにログインしているかを確認してください。 | `not_logged_in` |
| `4001017` | ログイン認証エラー：kabuSステーション未ログイン状態。 | | `not_logged_in` |
| `4001008` | API利用不可 | API利用設定が完了しているかを確認してください。 | `api_setup_incomplete` |
| `4001013` | トークン取得失敗：kabuステーションがログインしている状態で、APIパスワードが不正 | | `bad_password` |
| 上記以外のコード | 本ファイル §2 の該当行 | 同左 | `other` |

`4001007` の確認先はログインである。「APIを利用する」のチェック有無では置き換えない。`4001008` の確認先は API 利用設定が完了しているかである。`4001013` はログイン済みでパスワードが違う、という意味のまま扱う。

案内の日本語は `kabu-status-mcp.md` §6。公式メッセージは `official_message` に、上の表の「エラーメッセージ」列をそのまま入れる。
