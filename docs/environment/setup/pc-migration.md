# PC 移行手順（issue #1075）

PC の買い替え・故障のときに、Pitha trador のデータと設定を新しい PC へ移して、同じ状態から再開する手順。仕様は`requirements/functional/components-platform.md` §4.25（FR-MIGRATE-1〜7）、実装は`architecture/overview/flows.md` §10.8。

## 何が移り、何が移らないか

| 種類 | 移行ファイル（`.pitha-bundle`）に | 補足 |
|------|--------------------------|------|
| 注文・シグナル・Jev の判断・ラベル・キャリブレーション・成績・監視リスト・`market_snapshots`（DB に残っている行）など、DB のテーブルすべて | **入る** | テーブルは`sqlite_master`から列挙。取り込み前に件数を比較表で確認できる |
| 運用設定（`runtime_settings`のうち下の除外以外）: リスク・資金の値、ブローカーの選択、モデル・しきい値の設定など | **入る** | |
| API キー・パスワード・トークン・Slack Webhook URL・立花証券の認証 ID と第二暗証番号（`secrets`テーブル） | **入らない** | 入れる選択肢もありません。新しい PC で入れ直す |
| 立花証券の秘密鍵ファイルそのもの | **入らない**（もともと DB に無い） | 鍵ファイルを新しい PC へ自分でコピーし、そのパスを設定する |
| 設定のうち端末固有のもの: バックアップ先（`system.backup_dir`）・ログ先（`system.log_dir`）・秘密鍵のパス | **入らない** | 新しい PC のフォルダは別。新しい PC で設定し直す（取り込み前の新しい PC の値は残る） |
| バックアップのフォルダ（`backups/`、#890） | 入らない | DB の外の別フォルダ。必要なら手でコピー |
| `market_snapshots`の退避フォルダ（`snapshot_archive/`、#1072。90 日を超えて DB から消えた分） | 入らない | DB の外の別フォルダ。研究用に使うなら手でコピー |
| ログ（`logs/`） | 入らない | |

## 手順

### 1. 今までの PC（旧 PC）で書き出す

1. アプリを起動し、Settings →「システム」→「PC 移行」を開く（`/settings/maintenance#modal-migration`）。
2. 「移行ファイルを書き出す」を押し、`pitha-migration-<日時>.pitha-bundle`を保存する。アプリは動かしたままでよい（書き込み中でも整合した状態で書き出す）。
3. 保存したファイルを USB メモリ等で新 PC へ移す。ファイルには秘密情報は入っていないが、取引の記録は入っているので、第三者には渡さない。
4. 手でコピーするもの（任意）: `backups/`・`snapshot_archive/`（DB と同じ階層）、立花証券を使うなら秘密鍵ファイル。
5. 旧 PC のアプリは新 PC の確認が済むまで消さない。

### 2. 新しい PC（新 PC）にアプリを入れる

1. 旧 PC と**同じかそれより新しいバージョン**のアプリをインストールして起動する。ファイルのスキーマがアプリより新しいと取り込みは拒否される（古いバージョンのファイルは取り込める。新しい形に自動で更新される）。
2. 初回は Setup 画面（`/setup`）が出る。必須の接続情報（`JEV_API_KEY`など。ブローカーの選択に応じたもの）を入れて完了する。取り込みはこの後の Settings から行う（Setup が終わるまで Settings は開けない）。ここで入れた秘密情報は、取り込みでは上書きされず、そのまま残る。

### 3. 新 PC で取り込む

1. Settings →「システム」→「PC 移行」→「取り込み」で、旧 PC から持ってきた`.pitha-bundle`を選び「内容を確認」を押す。この時点では**何も変わらない**。
2. 表示を確認する: ファイルの作成日時・書き出したアプリのバージョン・データベースの版、テーブルごとの行数（現在／ファイル）。壊れた・書き換えられたファイル、秘密情報が入っているファイル、新しすぎるファイルは、ここで理由つきで拒否される。
3. 新 PC に既にデータがある場合は「現在のデータを、このファイルの内容で置き換えることを理解しました」にチェックを入れる（無いと予約できない）。
4. 「取り込みを予約する」→確認ダイアログで「実行する」。予約するとその旨と「再起動すると入れ替わります」が表示される（「予約した取り込みをやめる」で取り消せる）。
5. アプリを終了して、もう一度起動する。起動時（DB を開く前）に、①現在の DB の**安全コピー**を`<DB のフォルダ>/migration/safety/pitha-before-import-<日時>.db`へ作り、②新 PC の秘密情報とバックアップ先・ログ先・秘密鍵のパスを引き継ぎ、③ファイルの DB を現行バージョンに更新して、④入れ替える。結果は Settings の「PC 移行」に「前回の取り込み: 完了」（失敗なら理由と「元のデータのまま起動」）と表示され、ログにも残る。

### 4. 取り込み後に入れ直すもの

1. 取り込んだ設定のブローカーの選択に必要な接続情報が足りなければ、起動後に Setup 画面へ誘導される。表示に従って入れる（API キー・パスワード・立花証券の認証 ID と第二暗証番号。Slack Webhook URL など任意の接続は Settings の各カードで入れ直す）。
2. 立花証券を使う場合は、秘密鍵ファイルを新 PC に置き、Settings の「立花証券 e支店（接続設定）」で**新 PC でのパス**を設定する。
3. 外部のバックアップ先を Settings の「バックアップ先」で設定し直す（未設定でも既定の`backups/`へは保存されるが、同じディスクのためディスク故障には耐えない）。
4. ログ先を変えていた場合は Settings の「ログディレクトリ」で設定し直す。
5. Settings の「PC 移行」のテーブルの行数と、ホーム・成績の画面で、旧 PC と同じ状態であることを確認する。

## 安全コピーから元に戻す

取り込みの結果に不満があるときは、アプリを終了し、`<DB のフォルダ>/migration/safety/`の`pitha-before-import-<日時>.db`を DB ファイル（`pitha.db`）の場所へ置き換えて（同じフォルダの`pitha.db-wal`・`pitha.db-shm`は削除）、起動し直す。安全コピーには取り込み前の秘密情報（暗号化済み）が入っているので、このフォルダは新 PC の外へ持ち出さない。不要になったら手で削除する（自動では削除しない）。

## うまくいかないとき

| 症状 | 原因・対応 |
|------|-----------|
| 「より新しいバージョンのアプリで書き出されています」 | 新 PC のアプリが古い。アプリを更新してからやり直す |
| 「ファイルが壊れているか、書き換えられています」 | 転送中の破損など。旧 PC でもう一度書き出す（何も変更していない） |
| 「PC 移行ファイルではありません」 | 別のファイル（データエクスポートの ZIP 等）を選んでいる |
| 「取り込みの確認の有効期限が切れました」 | 確認のあとに別のファイルを確認した、またはアプリを再起動した。もう一度ファイルを選ぶ |
| 再起動後に「前回の取り込み: 失敗」 | 元のデータのまま起動している。理由を確認して、もう一度手順 3 を行う |
| ファイルが非常に大きい | 取り込みの上限は 4 GiB。超えると取り込めない（開発側へ連絡する） |
