# 手順書: J-Quants の日足・分足の取り込み（issue #1093）

`docs/environment/setup.md` から分割した章。J-Quants（有料）の日足・分足・銘柄一覧を、契約したときだけ研究専用の表へ取り込む読み取りアダプタの、設定・運用・解約の手順。設計は`docs/architecture/overview/integrations-jquants.md`、表は`docs/architecture/er/tables-jquants.md`、要件は`docs/requirements/functional/jquants.md`。

**この機能は既定でオフ**。キーを入れても、スイッチをオンにしても、契約していない側（日足・分足）のフラグをオンにしなければ、その側は一度も呼ばない。取り込んだデータは取引の判断・Risk・発注・Paper ガード・Live・Jev・RAG・Calibration・メタモデルの学習・自己改善に使わない。

## J-Quants の利用条件（守ること）

- **個人の私的利用の範囲**で使う。取り込んだデータを外部へ送らない（Slack・MCP・エクスポート・ログ・他人への共有など）。MCP のツール`jquants_status`は件数・日付・固定コードだけを返し、価格・銘柄・キーを返さない。
- **解約したら、生データと、元に戻せる派生物を削除する**。下の「解約したとき」の手順で、J-Quants 由来の行だけを削除できる。
- 要求数の上限（プランごとに毎分の上限がある。Light は毎分 60、分足のアドオンは毎分 60）を守る。アプリは要求の間を 1.5 秒以上あけ、`429`が返ったらその実行を止める。

## 契約したときの手順

1. J-Quants で契約し、API キー（V2。ヘッダ`x-api-key`で送る）を取得する（悠太さんが行う）。Light は月 1,650 円で日足 5 年分、分足は別に月 5,500 円のアドオンで過去 2 年分（翌日配信）。
2. アプリの Settings「外部連携・AI」ページの「J-Quants（日足・分足）」にキーを保存する（秘密として暗号化して保存。ログ・エラー・MCP の応答・研究用の表には出さない）。**キーはアプリの起動時に 1 回読むため、保存したら再起動する**（ほかの接続と同じ）。
3. 同ページの運用設定「J-Quants（日足・分足の取り込み）」で、次を決める。**既定はすべてオフ**で、Paper 実績 MCP からは変更できない。

| 項目 | キー | 既定 | 意味 |
|------|------|------|------|
| J-Quants の取り込み | `jquants.enabled` | 0（オフ） | スイッチ。オフの間は外部への要求が 0 回で、何も書かない |
| 契約: 日足 | `jquants.plan_daily` | 0 | 日足を契約しているときだけ 1。0 なら日足の API は呼ばない |
| 契約: 分足 | `jquants.plan_minute` | 0 | 分足のアドオンを契約しているときだけ 1。0 なら分足の API は呼ばない |
| 1 日の要求数の上限 | `jquants.daily_request_cap` | 200 | JST の 1 日に送る要求（ページ送りを含む）の上限（1〜5000）。上限に達したら、その日は止まり、翌日に続きを取る。数えは DB にあり、再起動しても戻らない |
| 埋め戻す日数 | `jquants.backfill_days` | 30 | 昨日からさかのぼって、取りこぼした日を探す日数（1〜1830）。分足は過去 2 年（730 日）より前を呼ばない |
| 取り込んだデータの削除 | `jquants.purge_requested` | 0 | 解約時に 1 にして保存する（下記）。終わると自動で 0（未設定）に戻る |

4. キーを入れ、スイッチと契約のフラグをオンにしたら、次のメンテナンスチェック（10 分以内。16:00 を待たない）から、昨日までの取りこぼした日を古い順に少しずつ取り込む。1 回の実行は短く区切られ、実行の合間に他のメンテナンス（バックアップなど）が動ける。初回の取り込みが長いときは、1 日の要求数の上限で何日かに分かれる。

## 何を取り込むか

- 銘柄一覧（`/v2/equities/master`）: 1 日 1 回。
- 日足（`/v2/equities/bars/daily?date=`）: 取引日ごとに全銘柄（ページ送りで`pagination_key`を追う）。
- 分足（`/v2/equities/bars/minute?code=&date=`）: アプリが`market_snapshots`に記録した銘柄だけ（取引日ごと）。分足は翌日に配信されるため、直近 3 日の空の応答は「まだ配信されていない」として印を付けず、次の実行で取り直す。
- 今日・休日は取らない。取得は印（`research_jquants_coverage`）のある単位を飛ばすので、何度実行しても同じ日を二重に取らず、行は自然キーで上書きされる（冪等）。

## 取りこぼした日のラベルの付け直し

日の分足をすべて取り込むと、その日の**研究用ホライズンラベル**（`research_horizon_labels`。#1074）のうち、`market_snapshots`の足が欠けて付かなかった窓（30 分・60 分・引け）だけを、J-Quants の分足を出口にして付け直す。

- 対象は研究用ラベルだけ。ライブのラベル・`calibration_outcomes`・`jev_*`・メタモデルの学習データには触れない。
- エントリーは`market_snapshots`の足のまま（分足には板が無く、エントリーにできない）。1 日まるごと`market_snapshots`が無い日は付け直せない。
- 付け直した行は`exit_source = 'jquants'`（記録部品が書いた行は`snapshot`）で区別でき、記録部品がすでに書いた行は書き換えない。日の集計（`research_label_day_stats`）は付け直した行を含めて作り直される。
- 記録部品がまだその日を完了していない日（`research.labels.enabled`がオフのときなど）は付け直さず、次の実行で再試行する。

## 状況の確認

Paper 実績 MCP の`jquants_status`（読み取り専用。`docs/api/endpoints/paper-results-mcp-jquants.md`）で、オン・オフ、契約のフラグ、上限と今日の要求数、表ごとの行数、期間内の日足・分足の日数、直近 7 日の失敗数と最後の失敗の固定コード、最後の成功の時刻を確認できる。失敗のコードは`http_401`（キーが拒否された）・`http_403`・`http_429`（要求が多すぎる。実行を止めて次回に回す）・`http_5xx`・`transport`・`decode`。401/403 と 429 はメンテナンスの失敗として通知される。

## 解約したとき（生データの削除）

1. Settings の運用設定「J-Quants（日足・分足の取り込み）」で、まず「J-Quants の取り込み」をオフにする。（取り込みがオンのまま、その日すでに実行が成功していると、削除の依頼は翌日の実行まで待つ。オフなら次のチェックで実行される。）
2. 「取り込んだデータの削除」をオンにして保存する。次のメンテナンスチェック（10 分以内）が、**キーもスイッチも要らず、外部へ要求を送らずに**次を削除し、この項目を自動でオフ（未設定）に戻す。
   - 取り込んだ生データ: `research_jquants_symbols` / `research_jquants_daily_bars` / `research_jquants_minute_bars`、取得済みの印`research_jquants_coverage`。
   - 元に戻せる派生物: `research_horizon_labels`のうち`exit_source = 'jquants'`の行（出口の価格から分足を逆算できるため）。削除したあと、その日の集計を残りの行から作り直す。
3. **削除されないもの**: `market_snapshots`・`daily_bars`・`disclosure_items`・`jev_*`・記録部品が書いたラベル（`exit_source = 'snapshot'`）など、J-Quants 由来でない行すべて。要求数の記録`research_jquants_fetch_log`（件数と固定コードだけ。市場データを含まず、消すと 1 日の上限の数えが日の途中で戻るため）。
4. 取り込みをオンのままにして削除を依頼した場合も、削除が先に実行され、その実行では取り込みをしない（次の実行から再び取り込む）。削除のあとに取り込みを続けたくないときは、先にオフにする。
5. J-Quants の API キー自体は、Settings「外部連携・AI」のキーの行から削除する（キーの削除は別の操作）。データベースのバックアップ（`daily/`・`weekly/`）には、バックアップ時点の J-Quants のデータが残る。解約時にバックアップも消す必要があるときは、バックアップのファイルを手動で削除する（アプリは過去のバックアップの中身を書き換えない）。

## 確認していないこと

実際の J-Quants はこの変更では呼んでいない（テストはモックと保存したサンプル応答）。契約・キーの入力・スイッチのオンは、マージ後に悠太さんかあいりが行う。契約前に、フィールド名や応答の形が公開仕様（J-Quants API V2）のとおりかを、少量の期間で確認すること。
